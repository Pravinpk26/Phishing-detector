# Intelligent Phishing Email Detector

## Overview

A phishing email detection system for Gmail, combining a **rule-based detection engine** with a **local AI/ML classifier (hybrid layer)**. It consists of:

- **Chrome Extension** — scans the currently opened Gmail email (or, in a limited "quick scan" mode, the inbox preview) and extracts sender, subject, body, and links
- **Node.js + Express backend** — analyzes the extracted email data and returns a phishing risk score with detailed reasons
- **React Dashboard** — displays scan results, risk factors, and scan history
- **Local TensorFlow.js model** — an additional AI-based signal that runs alongside the rule-based checks, giving each email a phishing-likelihood score independent of the hand-written rules

---

## How Detection Works

Every scanned email is evaluated across 6 weighted categories, combined into a single 0–100 risk score:

| Category | What it checks | Weight |
|---|---|---|
| Sender | High-risk TLDs, punycode tricks, typosquatted domains, brand impersonation | 15 |
| Urgency | Pressure language in the subject line ("URGENT", "verify now", all caps, etc.) | 10 |
| Content | Credential-harvesting phrases, generic greetings, urgency + credential-request combos | 15 |
| Links | Shorteners, IP-literal URLs, punycode, typosquatting, credential keywords in the path, unusually long URLs, link volume | 30 |
| Attachments | Dangerous file types, macro-enabled documents, double-extension tricks | 10 |
| **AI Model** | A local TensorFlow.js neural network's independent phishing-likelihood prediction on the email text | 20 |

Final score:
- **0–39** → Safe
- **40–79** → Suspicious
- **80–100** → Phishing

If any category is unavailable (e.g. the AI model hasn't been trained yet), the score is normalized over the remaining categories rather than silently under-scoring.

Every response includes a `reasons` array explaining *why* an email was flagged, plus an `ai: { score, confidence }` field showing the model's own prediction.

## Setup & Running the Project

### 1. Backend

```bash
cd backend
npm install
```

**Train the AI model** (only needed once, or after changing `vocabulary.js`/`trainingData.js`):
```bash
npm run train-model
```

**Start the server:**
```bash
node server.js
```
Runs on `http://localhost:5000`. If the model hasn't been trained yet, the server still runs fine — it logs a warning and falls back to rule-based scoring only.

**(Optional) Enable live URL reputation checks** via Google Safe Browsing:
```bash
# Windows PowerShell
$env:SAFE_BROWSING_API_KEY="your-key-here"
```
Without this, `urlReputation.js` still works using heuristics alone.

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```
Runs on `http://localhost:5173`.

### 3. Chrome Extension

1. Go to `chrome://extensions`
2. Enable **Developer mode**
3. Click **Load unpacked** → select the `frontend/extension` folder
4. Open Gmail, open an email, click the extension icon, then **Scan Current Email**

## API Reference

### `POST /analyze-email`
```json
{
  "sender": "security@example.com",
  "subject": "Verify your account",
  "body": "email text...",
  "links": ["https://example.com/..."],
  "attachments": ["invoice.pdf"]
}
```
Returns:
```json
{
  "score": 55,
  "reasons": ["..."],
  "sender": "...",
  "subject": "...",
  "links": ["..."],
  "riskLevel": "Suspicious",
  "breakdown": { "sender": {}, "urgency": {}, "content": {}, "links": {}, "attachments": {}, "ai": {} },
  "ai": { "score": 100, "confidence": 1 }
}
```

### `POST /analyze-url`
```json
{ "url": "http://example.com/suspicious-link" }
```
Returns `{ url, score, reasons }`.

### `GET /latest-scan`
Returns the most recently scanned email's full result (used by the dashboard).

## Known Limitations

- The AI model is trained on a small demo dataset (~80 hand-labeled examples) — a working proof of concept, not production-grade accuracy. Retrain on a larger real-world phishing/legitimate email corpus for better results (`npm run train-model` after updating `trainingData.js`).
- Scanning from the Gmail inbox list (without opening the email) only has access to sender, subject, and a short preview snippet — Gmail doesn't expose the full body or links until the email is opened, so this "quick scan" mode is inherently less accurate than scanning an opened email.
- Live URL reputation checking (Google Safe Browsing) is optional and requires an API key; without one, only heuristic checks run.
- `/latest-scan` uses in-memory storage — history is lost on server restart.
